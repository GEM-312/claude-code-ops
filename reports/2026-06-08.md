## What's New in Claude Code This Week

### v2.1.160 — `ultracode` keyword rename + security tightening

- **`ultracode` replaces `workflow` as the dynamic-workflow trigger keyword.** Typing "ultracode" in a prompt now triggers the workflow system; the old keyword `workflow` is retired. `/effort ultracode` CLI shortcut still works. Controlled via `workflowKeywordTriggerEnabled` in settings. Source: [CHANGELOG v2.1.160](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- `acceptEdits` mode now prompts before writing build-tool config files that grant code execution. Source: changelog v2.1.160
- `Edit` tool no longer requires a separate `Read` after a single-file `grep`/`egrep`/`fgrep` — reduces friction for grep-then-edit workflows. Source: changelog v2.1.160
- **`CLAUDE_CODE_OPUS_4_6_FAST_MODE_OVERRIDE` removed** (deprecated as of v2.1.154). Replacement: `/model claude-opus-4-6` then `/fast on`. Source: changelog v2.1.160
- Bug fixes: overnight session conversation loss; `claude agents` freeze on auto-updater re-check; vim mode `p` paste offset; improved background session teardown.

### v2.1.161 — Agent view + Linux clipboard

- `OTEL_RESOURCE_ATTRIBUTES` values included as metric datapoint labels. Source: changelog v2.1.161
- `/mcp` collapses unused claude.ai connectors behind "Show unused connectors" — cleaner MCP panel. Source: changelog v2.1.161
- Parallel tool calls: a failed Bash command no longer cancels other concurrently running calls in the same batch. Source: changelog v2.1.161
- Linux clipboard uses `wl-copy`/`xclip`/`xsel` in fullscreen mode when available. Source: changelog v2.1.161

### v2.1.162 — Agent JSON + `/effort` feedback

- **`claude agents --json` includes `waitingFor` field** showing what condition is blocking a background agent. Useful for scripting multi-agent workflows. Source: changelog v2.1.162
- **`--tools`: explicitly listing `Grep`/`Glob` now provides dedicated search tools** rather than falling back to Bash. Source: changelog v2.1.162
- `/effort` now confirms when the chosen level will persist as the session default. Source: changelog v2.1.162
- Remote Control shows as a persistent footer pill with session link (no longer a one-time startup notice). Source: changelog v2.1.162
- Fixed `WebFetch` permission rules not applying to preapproved domains. Source: changelog v2.1.162
- Fixed Windows permission rules not matching backslash paths or case variants. Source: changelog v2.1.162

### v2.1.163 — Stop hooks gain `additionalContext` + version guardrails (managed)

- **`requiredMinimumVersion` and `requiredMaximumVersion` managed settings** — org admins can pin Claude Code to a version range; Claude Code refuses to start outside it. Managed-only settings (enterprise/admin), not applicable to project-level `settings.json`. Source: changelog v2.1.163
- **`/plugin list` command** with `--enabled`/`--disabled` filters to list installed plugins. Source: changelog v2.1.163
- **Stop and SubagentStop hooks can now return `hookSpecificOutput.additionalContext`** — Claude receives feedback after a turn ends, keeping the turn alive without labeling it a hook error. New pattern: post-process output and redirect Claude's next action from a Stop hook. Source: changelog v2.1.163
- **Skill `$` escape syntax**: use `\$` for a literal `$` before digits in command bodies to prevent substitution. Source: changelog v2.1.163
- Fixed **`if: "Bash(...)"` conditions firing on every command containing `$()` or `$VAR`** — prior bug caused hooks with shell-variable patterns to fire too broadly. Source: changelog v2.1.163
- Fixed **deny rules on home-directory paths not blocking commands using `$HOME`** — security fix: deny rules now correctly block `$HOME/path/to/file` references that match absolute deny entries. Source: changelog v2.1.163
- Fixed `claude -p` hanging after final result when a backgrounded command never exits. Source: changelog v2.1.163
- Fixed org-managed permission rules not applying when fetch completed mid-startup. Source: changelog v2.1.163

### v2.1.164, v2.1.165

- Bug fixes and reliability improvements only.

### v2.1.166 — `fallbackModel` + glob deny rules (NOTABLE)

- **`fallbackModel` setting** — specify up to 3 backup models tried in order when the primary is unavailable. New key in `settings.json`. Source: changelog v2.1.166
- **Glob pattern support in deny rule tool-name position** — deny rules now accept patterns like `mcp__github__*` to deny all tools on an MCP server. **Counterpoint: allow rules now REJECT non-MCP globs in the tool-name position.** Existing allow rules using exact tool names (`Bash`, `Read`, etc.) are unaffected. Source: changelog v2.1.166
- Hardened cross-session messaging: relayed messages no longer carry user authority (security fix). Source: changelog v2.1.166
- `MAX_THINKING_TOKENS=0`, `--thinking disabled`, and per-model thinking toggle now correctly disable thinking on Opus 4.8. Source: changelog v2.1.166
- Claude Code retries once on fallback model when the API returns unexpected non-retryable errors. Source: changelog v2.1.166
- Fixed **managed settings with invalid entries silently disabling remaining policies** — previously one bad rule could knock out all subsequent allow/deny entries. Source: changelog v2.1.166
- Fixed orphaned `claude --bg-pty-host` processes spinning at 100% CPU on macOS. Source: changelog v2.1.166
- Fixed recurring "image could not be processed" error and extra token usage. Source: changelog v2.1.166
- Fixed remote sessions permanently stuck after backend disruption during worker registration. Source: changelog v2.1.166
- Fixed JetBrains IDE terminal flickering on 2026.1+ (synchronized output). Source: changelog v2.1.166

### v2.1.167, v2.1.168

- Bug fixes and reliability improvements only.
