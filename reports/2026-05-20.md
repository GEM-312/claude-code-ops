## What's New in Claude Code This Week (v2.1.139 – v2.1.145)

Versions released approximately May 13–19, 2026. Dates sourced from [claudeupdates.dev](https://www.claudeupdates.dev) and [Releases · anthropics/claude-code](https://github.com/anthropics/claude-code/releases).

### v2.1.139
- **Agent view dashboard** — `claude agents` command opens a new TUI showing all running background sessions
- **`/goal`** — new slash command to set a completion condition for the current session
- **`/scroll-speed`** — customize mouse wheel sensitivity in the TUI

### v2.1.140
- `subagent_type` matching in the Agent tool is now **case-insensitive** — fixes agents failing to dispatch when case didn't match registered type names
- Background service startup hardened for machines with enterprise security software

### v2.1.141
- **`terminalSequence` hook field** — hook JSON output can now include a `terminalSequence` key to emit OSC/CSI sequences: desktop notifications, window titles, terminal bells. Requires v2.1.141+. Source: [hooks docs](https://code.claude.com/docs/en/hooks)
- `ANTHROPIC_WORKSPACE_ID` env var added for workload identity federation

### v2.1.142
- `claude agents` supports configuration flags for dispatched background sessions: `--add-dir`, `--settings`, `--mcp-config`, `--plugin-dir`

### v2.1.143 — May 16
- **Plugin dependency enforcement** — `claude plugin disable` refuses when another enabled plugin depends on the target (provides `--disable-chain` hint to cascade)
- **`worktree.bgIsolation: "none"`** — new setting; background sessions edit the working copy directly without entering a worktree
- Projected context costs added to `/plugin` marketplace browse pane
- Source: [claudeupdates.dev](https://www.claudeupdates.dev)

### v2.1.144 — May 19
- **`/model` is now session-only by default** ⚠️ — changing the model in a session no longer persists to new sessions. Press `d` in the model picker to set a persistent default. Behavior change from prior versions.
- **`/resume` lists background sessions** — sessions started with `--bg` or via the agent view now appear alongside interactive sessions in `/resume`
- **"Usage credits"** — `/extra-usage` renamed to `/usage-credits` (old command still works)
- 75-second startup hang on unreachable API → fixed to 15-second timeout
- 40+ additional bug fixes
- Source: [claudeupdates.dev](https://www.claudeupdates.dev)

### v2.1.145
- **Three new bundled skills** (require v2.1.145+). Source: [skills docs](https://code.claude.com/docs/en/skills)
  - **`/run`** — launch and drive your app to confirm a change works against the real running app
  - **`/verify`** — build and run to confirm a code change does what it should (does not fall back to type checks)
  - **`/run-skill-generator`** — records your project's build/launch recipe once into `.claude/skills/run-<name>/`, making `/run` and `/verify` reliable for non-standard setups (e.g., Xcode projects needing a specific scheme and destination)
- `claude agents --json` — machine-readable output for scripting the agent view
- Improved plugin discovery screens showing commands, agents, skills, and MCP/LSP servers before install

### Skills system (docs refresh, active across versions)
Several frontmatter fields are now documented / GA. Source: [skills docs](https://code.claude.com/docs/en/skills)

| New field | What it does |
|---|---|
| `disable-model-invocation: true` | Prevents Claude from auto-loading the skill; user must invoke via `/name` |
| `user-invocable: false` | Hides skill from `/` menu but keeps Claude auto-trigger |
| `effort: high` | Overrides session effort level while skill is active |
| `model: <id>` | Overrides session model while skill is active (session-scoped, not saved) |
| `paths: ["glob"]` | Skill auto-activates only when working with matching files |
| `context: fork` | Runs skill in an isolated subagent context |
| `argument-hint: "[arg]"` | Shows hint during `/` autocomplete |
| `hooks` | Hooks scoped to this skill's lifecycle |
| `${CLAUDE_SKILL_DIR}` | Expands to the skill's own directory (useful for bundled scripts) |
| `${CLAUDE_EFFORT}` | Expands to current effort level |

**Key note:** `user-invocable` uses a **hyphen**, not underscore. `user_invocable` is silently ignored.
